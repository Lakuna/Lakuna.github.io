# TUTOR Commands

The following is an alphabetical list of commands in the TUTOR language. It is not comprehensive. One of the sources, _The TUTOR Language_ by Bruce Anne Sherwood, has a Wiki version [here](https://codex.retro1.org/plato:tutor:start). Other sources include _Introduction to TUTOR_ by James R. Ghesquiere and the `introtutor` and `aids` lessons (accessed via [cyber1](https://cyber1.org/)). To see a complete description of any command, refer to the `aids` lesson.

You can find my overview of the TUTOR language [here](../tutor).

## List of Commands

### `ansv`

**Judging command.**

```
ansv    expression[,tolerance]
```

Judge a numeric or algebraic answer. If the response matches `expression` within the specified `tolerance`, an `ok` judgment is given. `tolerance` may be specified as a range (such as `10`) or a percentage deviation (such as `2%`). If no `tolerance` is given, an exact answer is required.

### `answer`

**Judging command.**

```
answer  [expression]
```

Judge an alphanumeric answer or some simple numerical responses. If the response matches `expression`, an `ok` judgment is given and `ok` is displayed on the screen after the response. Punctuation marks can't appear in `expression`. If no `expression` is given, the response will match if it is a space, NEXT, a `jkey`, `jcount` is `0`, a TUTOR punctuation mark (such as `;`, `,`, `.`, or `$`), or any touch if the touch panel is enabled. _Required words_ listed in `expression` must appear in the response.

Can't match a response over 39 words.

_Synonymous words_ are separated by commas or spaces and enclosed in parentheses. Words that can be ignored are enclosed in angle brackets. Commas are used to separate synonymous responses. `*` is used between words of a phrase.

There are automatic checks for spelling, extra words, word order, capitalization, missing words, and broken phrases that can be modified with `specs`. The closest matching answer is used for markup feedback. The following markups are possible:

- `===`: the word is misspelled.
- `↑`: the first letter of the word needs to be capitalized.
- `***`: the word is part of a broken phrase.
- `⇦`: the word is out of order (needs to be moved left).
- `⇦==`: the word is misspelled and out of order (needs to be moved left).
- `Δ`: the word implies something missing.
- `Δ==`: the word is misspelled and implies something missing.
- `↑⇦`: the first letter of the word needs to be capitalized and the word is out of order (needs to be moved left).
- `Δ↑`: the first letter of the word needs to be capitalized and the word implies something missing.
- `xxx`: the word is extra.

### `arrow`

```
arrow   position
```

Plot an arrow on the screen at coarse grid position `position` and start a judging block.

```
arrow   positionx,positiony
```

Plot an arrow on the screen at fine grid position `positionx,positiony` and start a judging block.

TUTOR continues to execute any regular commands until it encounters a judging command, then waits for a student response. See more details about judging blocks in my overview of the TUTOR language [here](../tutor#judging-blocks). Has default settings of `long    150`, `jkey    next`, an active EDIT key, and a disabled COPY key. The levels of `do` and `join`, writing size, and degree of rotation are also saved. Sets `where` to the next character position. After a judgment, `where` is set to the arrow location plus `302`. If used in an attached unit, the attached unit must contain an `endarrow` command and must not contain a `goto` command.

### `back`

**Regular command.**

```
back    [unit]
```

Specify that unit `unit` will become the new main unit when the user presses BACK. No `unit` or a `unit` of `q` clears the pointer.

```
back    expression,...units
```

Specify that the unit specified by the conditional tag will become the new main unit when the user presses BACK. See my TUTOR overview [here](../tutor#conditional-operations) for more information about conditional operations. An `x` argument leaves the pointer unchanged and a `q` argument clears the pointer (returning the key to its default action).

The default action of BACK is to be inactive except in help sequences, where the default action is to return to the base unit. This does not allow the passing of arguments to units because the pointers for the commands are set when the command is encountered (rather than at the time when the branch occurs).

### `base`

**Regular command.**


Set the base unit (`baseu`) to unit `unit`, or clear the base unit if there is no `unit`. No `unit` or a `unit` of `q` clears the base unit.

### `bounds`

**Regular command.**

```
bounds  xmax,ymax
```

Establish positive boundaries on the horizontal and vertical axes relative to the origin. `xmax` is the horizontal maxiumum boundary and `ymax` is the vertical maximum boundary.

```
bounds  xmin,ymin,xmax,ymax
```

Establish positive and negative boundaries on the horizontal and vertical axes relative to the origin. `xmin` is the horizontal minimum boundary, `ymin` is the vertical minimum boundary, `xmax` is the horizontal maxiumum boundary, and `ymax` is the vertical maximum boundary.

All arguments are measured in screen dots. Upon entering a lesson, the boundaries are automatically set to the entire screen (`511,511`).

### `box`

**Regular command.**

```
box     [position0][;position1][;thickness]
```

Draw a rectangular box. `position0` and `position1` are the positions of opposite corners of the box; they can each be either a single number `position` representing a coarse grid position or two comma-separated numbers `positionx,positiony` representing fine grid coordinates. `thickness` specifies how many dots thick the walls of the box should be, with negative values extending into the box from the corners and positive values extending out of the bot from the corners. `thickness` values of `-1`, `0`, `1`, and unspecified all make a box with walls that are 1 dot thick. If neither `position0` nor `position1` are specified, a box will be drawn from `0,0` to `511,511`, affected by `gorigin` (other forms of the command are not affected by `gorigin`). If only `position0` is specified, a box is drawn from `0,0` to `position0`. If only `position1` is specified, a box is drawn from `wherex,wherey` to `position1`.

`where`, `wherex`, and `wherey` are set to the lower-left corner of the box for boxes with positive thickness or the lower-left corner of the innermost box for boxes with negative thickness.

### `branch`

**Regular command.**

```
branch  label
```

Branch to statement label `label` in the current unit.

```
branch  expression,...labels
```

Branch to the statement label specified by the conditional tag. See my TUTOR overview [here](../tutor#conditional-operations) for more information about conditional operations.

Cannot branch between units or around `entry` commands. If a `branch` command or statement label follows a non-`calc` command, it initiates a `calc` command. The tag may not extend across multiple lines (subsequent lines without a command name are treated as a `calc` command). This command is faster than `doto` but not quite as fast as `loop`. The condenser, step-mode, and execution error routines all treat `branch` commands and statement labels as if they were `calc` commands. `branch` can appear in the tag field instead of the command field to continue the current `calc`, in which case it may be followed by 1-2 spaces. If a branch goes over an `endarrow`, the branch is done, but execution will return to the `endarrow` once all the commands below the statement label are executed.

### `define`

**Non-executable command.**

```
define  ...definitions
```

Define variables, constants, functions, segments of variables, and arrays of variables. `definitions` is a comma- or newline-separated list of definitions. To define a meaningful name for a variable, use a definition of the form `name=variable`, where `name` is the meaningful name and `variable` is the primitive name of the variable (for example, `problem=v1`). To define a meaningful name for a constant, use a definition of the form `name=expression`, where `name` is the meaningful name and `expression` is the value of the constant. To define a name for a `define` set, use a definition that is just the name of the set as the first definition. To include another `define` set in a `define` set, use a definition that is just the name of the subset (for any definition other than the first).

```
define  segment,name=variable,bits[,signed]
```

Define a horizontally segmented variable. `segment` is a literal value, `name` is the meaningful name, `variable` is the primitive name, `bits` is the number of bits per segment (up to `59`), and `signed` is a literal value of either `signed` or `s` (the variable is signed if this is included or unsigned if it is omitted). `variable` must be a direct reference to a variable and `bits` must be a constant value.

```
define  segmentv,name=variable,start,bits[,signed]
```

Define a vertically segmented variable. `segmentv` is a literal value of either `segment,vertical` or `segmentv`, `name` is the meaningful name, `variable` is the primitive name, `start` is the 1-based starting bit index, `bits` is the number of bits per segment (up to `59`), and `signed` is a literal value of either `signed` or `s` (the variable is signed if this is included or unsigned if it is omitted). `variable` must be a direct reference to a variable and `bits` must be a constant value.

```
define  segmentf,name=variable,start,bits[,signed]
```

Define a field (which counts as a segment). `segmentf` is a literal value, `name` is the meaningful name, `variable` is the primitive name, `start` is the 1-based starting bit index, `bits` is the number of bits per segment (up to `59`), and `signed` is a literal value of either `signed` or `s` (the variable is signed if this is included or unsigned if it is omitted). `variable` must be a direct reference to a variable and `bits` must be a constant value.

```
define  array,name[(rows[,columns][;endrow[,endcolumn]])]=variable
```

Define an array. `array` is a literal value, `name` is the meaningful name, `rows` is the number of rows in the array if `endrow` is not defined or the index of the first row in the array otherwise, `columns` is the number of columns in the array if `endcolumn` is not defined or the index of the first column in the array otherwise, `endrow` is the index of the last row in the array (the array will have `endrow-rows` rows), `endcolumn` is the index of the last column in the array (the array will have `endcolumn-columns` columns), and `variable` is the primitive name. If none of `rows`, `columns`, `endrow`, or `endcolumn` (or the parentheses around them) are given, a 0-dimensional array (scalar) is defined instead. `rows`, `columns`, `endrow`, `endcolumn`, and `variable` must be literals or defined constants.

```
define  arraysegv,name[(rows[,columns][;endrow[,endcolumn]])]=variable,start,bits[,signed]
```

Define an array using vertical segments. `arraysegv` is a literal value, `name` is the meaningful name, `rows` is the number of rows in the array if `endrow` is not defined or the index of the first row in the array otherwise, `columns` is the number of columns in the array if `endcolumn` is not defined or the index of the first column in the array otherwise, `endrow` is the index of the last row in the array (the array will have `endrow-rows` rows), `endcolumn` is the index of the last column in the array (the array will have `endcolumn-columns` columns), `variable` is the primitive name, `start` is the 1-based starting bit index, `bits` is the number of bits per segment (up to `59`), and `signed` is a literal value of either `signed` or `s` (the variable is signed if this is included or unsigned if it is omitted). If none of `rows`, `columns`, `endrow`, or `endcolumn` (or the parentheses around them) are given, a 0-dimensional array (scalar) is defined instead. `rows`, `columns`, `endrow`, `endcolumn`, and `variable` must be literals or defined constants.

```
define  name[(...arguments)]=expression
```

Define a function. `name` is the name of the function, `arguments` is the comma-separated list of names of arguments to the function, and `expression` is the expression that is evaluated and returned by the function. `arguments` cannot contain an argument name that is the same as a previously-defined name. `expression` must be valid when enclosed in parentheses. `arguments` may contain no more than 6 argument names. `expression` may be of the form `(variable⇦expression)`, in which case the value of the variable `variable` is set to the result of the expression `expression` and returned.

```
define  name
```

Activate the `define` set named `name`.

```
define  purge[,name]
```

Discard the `define` set named `name`, or all existing `define` sets aside from `student` if no `name` is given. `purge` is a literal value.

```
define  units,...names
```

Define a list of _primary units_ for use with `storeu`, `ansu`, and `wrongu`. `units` is a literal value and `names` is a comma-separated list of primary unit names. There can be up to 10 primary units (but each can have _equivalent units_ defined further in the `define` set). Primary units can only be defined in `student`.

Defined names must be 7 or fewer characters long, can't begin with a number, can't begin with any of `o`, `n`, `v`, `nc`, `vc`, `nr`, or `vr` followed by a number, can't contain FONT characters, can't contain backspaces, can't contain mathematical operators, and can't contain any of `$`, `#`, `%`, `?`, `Σ`, `Δ`, `°`, or `π`.

The `define` command must physically precede any reference to any of the defined names; it is usually placed in the initial entry unit. If no `define` set has a name, all previous `define` sets will be in effect; otherwise, the previous `define` sets will not be in effect (unless they are part of the most recent `define` set). Only 5 `define` sets may be active at once; when a sixth is encountered (at condense time), the previous 5 are discared (`student`). The special `define` set named `student` allows the user to use variables defined within it in their responses. `student` may contain up to 500 variables, all of which work only with `ansv`, `ansu`, `wrongv`, `wrongu`, `store`, `storeu`, and `compute`.

### `stop`

**Regular command.**

```
stop    [unit]
```

Specify that unit `unit` will become the new main unit when the user presses STOP. No `unit` or a `unit` of `q` clears the pointer.

```
stop    expression,...units
```

Specify that the unit specified by the conditional tag will become the new main unit when the user presses STOP. See my TUTOR overview [here](../tutor#conditional-operations) for more information about conditional operations. An `x` argument leaves the pointer unchanged and a `q` argument clears the pointer (returning the key to its default action).

The default action of STOP is to abort output to the terminal screen, and this is done regardless of whether a branch occurs. This does not allow the passing of arguments to units because the pointers for the commands are set when the command is encountered (rather than at the time when the branch occurs).

### `unit`

**Regular command.**

```
unit    name[(...arguments)]
        [type: ][...localvariables]
```

Identify a unit of code. `name` is the name of the unit, `arguments` is the comma-separated list of names of input variables to the unit, `type` is the type of the local variables declared on that line (either `floating` or `integer`, equivalent to the `type` of the previous line if not specified or `floating` if there was no previous line), and `localvariables` is the comma- or newline-separated list of names of local variables within the unit. `name` cannot be longer than 8 characters and can't be `x` or `q`. Each input variable listed in `arguments` must also be listed in `localvariables` if they are to be local variables (arguments can also be stored in global variables). `arguments` can't contain more than 10 names. Local variables can be arrays (for example, a local variable named `foo(4)` would define local variables `foo(1)` through `foo(4)`). Globally defined variables may be merged with local variables by including the `define` set name in `localvariables` (a unit that has local variables may not use global variables otherwise).

A unit ends when it encounters the start of the next unit or the end of the lesson. Units can't be longer than 1023 condensed words. Lessons can't contain more than 750 units. Input arguments can be passed to a unit with `do`, `jump`, `goto`, `join`, and `jumpn` by including comma-separated expressions in parentheses after the unit name corresponding to the arguments defined in the unit. Not all arguments need to be passed values; for arguments stored in local variables, the value will be undefined, and for arguments stored in global variables, the value will remain as it was before the call. If the unit has `return` values, they should be included in the same set of parentheses as the arguments, separated from each other by commas and separated from the arguments by a semicolon (for example, `do      foo(1,2;a,b)` would pass `1` as the value of the first argument and `2` as the value of the second to unit `foo` and would receive the first `return` value from `foo` in variable `a` and the second in variable `b`). Return values can be used with `do` and `join`.

### `wrong`

**Judging command.**

```
wrong   [expression]
```

Judge an alphanumeric answer or some simple numerical responses. If the response matches `expression`, a `wrong` judgment is given and `no` is displayed on the screen after the response. Punctuation marks can't appear in `expression`. If no `expression` is given, the response will match if it is a space, NEXT, a `jkey`, `jcount` is `0`, a TUTOR punctuation mark (such as `;`, `,`, `.`, or `$`), or any touch if the touch panel is enabled. _Required words_ listed in `expression` must appear in the response.

Can't match a response over 39 words.

_Synonymous words_ are separated by commas or spaces and enclosed in parentheses. Words that can be ignored are enclosed in angle brackets. Commas are used to separate synonymous responses. `*` is used between words of a phrase.

There are automatic checks for spelling, extra words, word order, capitalization, missing words, and broken phrases that can be modified with `specs`.

### `wrongv`

**Judging command.**

```
wrongv  expression[,tolerance]
```

Judge a numeric or algebraic answer. If the response matches `expression` within the specified `tolerance`, a `no` judgment is given. `tolerance` may be specified as a range (such as `10`) or a percentage deviation (such as `2%`). If no `tolerance` is given, an exact answer is required.
